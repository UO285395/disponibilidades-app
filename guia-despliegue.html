Paso 1

1

Crear la base de datos en Neon

La base de datos es donde la aplicación guarda toda la información (usuarios, eventos, disponibilidades…). Neon la ofrece gratis para proyectos pequeños.

1

Entra en neon.tech y crea una cuenta

Haz clic en Sign Up. Puedes registrarte con tu cuenta de Google o con un email y contraseña.

2

Crea un nuevo proyecto

Después de entrar, Neon te pedirá que crees un proyecto. Ponle el nombre que quieras (por ejemplo: disponibilidad). Elige la región Europe (Frankfurt). Haz clic en Create project.

3

Copia la cadena de conexión

Neon mostrará una pantalla con la información de conexión. Haz clic en el botón Copy que hay junto al campo llamado Connection string o DATABASE_URL. Guarda ese texto en un bloc de notas, lo necesitarás pronto.

El texto copiado tendrá un aspecto parecido a este:

Ejemplo (el tuyo será diferente)
postgresql://usuario:contraseña@ep-abc-123.eu-central-1.aws.neon.tech/neondb?sslmode=require
✅
Listo con Neon Ya tienes tu base de datos. Guarda bien la cadena de conexión que copiaste: es tu DATABASE_URL y la usarás en el siguiente paso.

Paso 2

2

Desplegar el servidor en Render

El servidor es el motor de la aplicación. Render lo ejecuta de forma gratuita y lo mantiene en marcha.

⚠️
El servidor puede tardar unos segundos en responder la primera vez En el plan gratuito, si nadie usa la esta usando se pone en reposo para no consumir recursos. Al volver a entrar, tarda unos segundos en arrancar. Esto es normal.
1

Entra en render.com y crea una cuenta

Haz clic en Get Started for Free. Puedes usar tu cuenta de GitHub para registrarte (es lo más cómodo).

2

Crea un nuevo servicio web

En el panel de Render, haz clic en el botón + New (arriba a la derecha) y luego en Web Service.

3

Conecta el repositorio de GitHub

Render te pedirá que conectes tu cuenta de GitHub. Haz clic en Connect account y autoriza el acceso. Después, busca el repositorio de la aplicación (la URL que te proporcionó la persona técnica) y haz clic en Connect.

4

Configura el servicio

Rellena los campos del formulario así:

Campo Valor
Name disponibilidad-backend (o el nombre que quieras)
Region Frankfurt (EU Central)
Branch distribucion-comites
IMPORTANTE, una branch es una "version" de la aplicacion, es importante escoger la adecuada
Root Directory backend
Runtime Python 3
Build Command pip install -r requirements.txt
Start Command uvicorn main:app --host 0.0.0.0 --port $PORT
Instance Type Free
5

Añade las variables de entorno

Más abajo en el mismo formulario verás una sección llamada Environment Variables. Haz clic en Add Environment Variable y añade estas cuatro variables:

Nombre (Key) Valor (Value)
DATABASE_URL obligatorio Pega aquí la cadena de conexión que copiaste de Neon en el Paso 1
SECRET_KEY obligatorio Una contraseña larga y aleatoria. Puedes inventarte una (mezcla letras, números y símbolos, mínimo 32 caracteres). No la pierdas.
INITIAL_ADMIN_EMAIL solo 1ª vez El email con el que quieres entrar como administrador por primera vez (p.ej. admin@tupartido.es)
INITIAL_ADMIN_PASSWORD solo 1ª vez La contraseña provisional para ese primer administrador. Cámbiala en la app justo después de entrar.
⚠️
Importante — elimina las variables de arranque después del primer acceso Las variables INITIAL_ADMIN_EMAIL e INITIAL_ADMIN_PASSWORD son solo para crear el primer administrador. Una vez hayas entrado a la app con esas credenciales, vuelve a Render, edita el servicio y elimina esas dos variables. Así nadie podrá usarlas para acceder.
6

Haz clic en «Create Web Service» y espera

Render tardará entre 3 y 8 minutos en preparar y arrancar el servidor la primera vez. Verás un registro de actividad en pantalla. Cuando aparezca el mensaje Your service is live 🎉, el servidor está listo.

Apunta la URL del servidor: aparece en la parte superior de la página, con un formato parecido a:

https://disponibilidad-backend.onrender.com

Guárdala, la necesitarás en el Paso 3.

Paso 3

3

Publicar la web en Netlify

La web es lo que verán los usuarios en el navegador. Netlify la publica de forma gratuita y rápida.

1

Entra en netlify.com y crea una cuenta

Haz clic en Sign up. Puedes registrarte con tu cuenta de GitHub.

2

Crea un nuevo sitio desde GitHub

En el panel de Netlify, haz clic en Add new site → Import an existing project. Elige GitHub y autoriza el acceso si te lo pide. Después, selecciona el repositorio de la aplicación.

3

Configura la publicación

Rellena los campos de configuración así:

CampoValor
Branch to deploy distribucion-comites
Base directory frontend
Build command npm run build
Publish directory frontend/dist
4

Añade la variable de entorno antes de publicar

En esa misma pantalla, busca la sección Environment variables (puede que tengas que hacer clic en Show advanced). Añade esta variable:

Nombre (Key) Valor (Value)
VITE_API_URL obligatorio La URL del servidor que guardaste al final del Paso 2 (p.ej. https://disponibilidad-backend.onrender.com). Sin barra al final.
5

Haz clic en «Deploy site»

Netlify tardará 1–3 minutos en construir y publicar la web. Cuando termine, verás un enlace verde con la dirección de tu web, algo como:

https://nombre-aleatorio-12345.netlify.app

Puedes cambiar ese nombre por uno más legible en Site settings → Domain management → Site name.

✅
La web ya está publicada Ahora tienes la aplicación en marcha. Cualquier miembro del comité puede acceder desde el navegador, sin instalar nada.

Paso 4

4

Primer acceso y configuración inicial

La primera vez que entres tendrás que configurar la estructura básica de la organización.

1

Entra en la aplicación con el administrador provisional

Abre la URL de Netlify en el navegador. En la pantalla de inicio de sesión, escribe el email y la contraseña que pusiste en las variables INITIAL_ADMIN_EMAIL e INITIAL_ADMIN_PASSWORD durante el Paso 2.

ℹ️
Si la pantalla tarda mucho en cargar la primera vez, es normal.
2

Cambia la contraseña

Ve a tu perfil (icono de usuario arriba a la derecha) y cambia la contraseña.

3

Elimina las variables de arranque en Render

Vuelve a render.com, entra en tu servicio y ve a Environment. Elimina las variables INITIAL_ADMIN_EMAIL e INITIAL_ADMIN_PASSWORD. Render pedirá confirmación para reiniciar el servicio: acepta. Este paso es obligatorio para proteger la aplicación.

4

Configura la estructura del comité

En el panel de administración verás la sección Organigrama. Desde allí podrás crear los colectivos y comites necesarios. Esto es importante para evitar el horizontalismo.

5

Añade el resto de militantes

Ve a Usuarios → Añadir usuario para crear las cuentas de los demás. La contraseña provisional la estableces tú; ellos podrán cambiarla al entrar. Por defecto, deberias asignar a cada militante a su colectivo de base aunque sea miembro del comite. Como miembro del comite asigna solo a aquellas personas que quieras qu etengan permiso sobre estructuras inferiores.

Opcional pero recomendado

⏰

Evitar que el servidor entre en reposo

En el plan gratuito de Render, el servidor se "duerme" si nadie lo usa durante 15 minutos. Para evitarlo (ahorrarse esos segundos de carga), configura un ping automático gratuito con cron-job.org.

1

Entra en cron-job.org y crea una cuenta gratuita

2

Crea un nuevo cronjob

Haz clic en CREATE CRONJOB y rellena:

  • URL: la URL de Render seguida de /docs (ej: https://disponibilidad-backend.onrender.com/docs)
  • Execution schedule: Every 10 minutes

3

Guarda y olvídate

A partir de ahora, cron-job.org enviará un pequeño mensaje al servidor cada 10 minutos para mantenerlo despierto. No se requiere ninguna otra configuración.
